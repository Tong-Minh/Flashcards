# Flashcards

Mobile-first flashcard PWA with FSRS spaced repetition. Next.js 15 (App Router) + React 19 + Tailwind 3 + Supabase.

## Commands

- `npm run dev` — dev server
- `npm run build` — production build (also the type check; there are no tests or linter)
- `npm run dev:desktop` / `npm run build:desktop` — the desktop target in a browser (browser-storage library, no login) / its static export to `out/` (both via `scripts/desktop.mjs`)
- `npm run desktop:dev` / `npm run desktop:build` — the Tauri app (needs Rust and the MSVC build tools; CI builds it otherwise)

## Architecture

- **Client-only app.** Every page is `'use client'`. Pages read and write the user's own sets through `store` (`lib/store`, see Desktop app below); social features (friends, discover, sharing, `fork_set`, shared collections) call Supabase directly via `lib/supabase/client.ts`. There are no API routes or server components doing data work, except link previews: `app/sets/[id]/layout.web.tsx` and `app/collections/[id]/layout.web.tsx` render Open Graph metadata and `opengraph-image.web.tsx` renders the preview image, via the `share_preview` RPC (callable logged out, public items only). Code for them is in `lib/sharePreview.ts` and `lib/shareImage.tsx`. Next.js blocks `react-dom/server` there, so the image builds icon SVGs from the vanilla `lucide` package. Access control is enforced entirely by Postgres RLS.
- **Auth:** `components/AuthGuard.tsx` wraps the app, exposes `useUser()`, and redirects to `/login`. DB triggers fill in `user_id` on insert for `sets`, `card_progress`, `study_sessions`, and `collections`.
- **Offline-first caching:** `lib/storage.ts` caches sets, cards (with progress), and sessions in localStorage. Pages render from the cache first, then refresh from Supabase. FSRS progress updates made offline are queued (`queueProgressUpdate`) and synced on the next study-page load.
- **FSRS:** `ts-fsrs` runs client-side in `app/sets/[id]/study/page.tsx`. Progress is upserted to `card_progress` on `(user_id, card_id)`. `status` is derived from FSRS state (`mastered` = Review with interval ≥ 21 days).
- **Rich content:** Card text is stored as a lightweight markup string (`**bold**`, `*italic*`, `***both***`, `` `code` ``, `[red]…[/red]`, `# headings`, `- ` / `1. ` list lines (one level), fenced code, `$math$`, a line that is only `$$math$$` = centered math block, a line that is only `![alt](images/<file>)` = image (desktop app only; `matchImageLine`), backslash escapes for literal `\ * $ ` [ ] # - .`).
  - `lib/markup.ts` is the single source of truth: the inline tokenizer plus markup ⇄ Tiptap JSON conversion. Its line helpers (`matchListLine`, `isMathBlockLine`) are shared with the renderer. The serializer escapes paragraphs that would otherwise re-parse as a heading or list item.
  - `components/ContentRenderer.tsx` renders markup read-only (Prism + KaTeX).
  - `components/BlockEditor.tsx` is the WYSIWYG editor. It splits text around code fences into text blocks (Tiptap editors, extensions in `components/editor/`) and code cards. Users never see raw markup while editing. `singleLine` mode is used for multiple-choice options.
  - The editor emits changes only on real edits (`setContent(..., { emitUpdate: false })` on load), so opening a card never rewrites its stored text. Keep it that way: MC correctness is a string comparison between `answer` and `options[i]`.
  - Every code block in the editor is followed by a text block (possibly empty), so there's always somewhere to click below it. Backspace at the start of that text highlights the code block, and a second Backspace deletes it.
  - The AI prompt (`app/sets/[id]/import/page.tsx`) and `/import-format` document the markup. Update them when the format changes. The tab-format importer converts `\n` into newlines everywhere except inside `$…$` math.
  - A single newline touching a code fence is a separator, not a blank line. The editor stores it as `lead`/`trail` flags on text blocks, and the renderer strips it. Both must keep treating it that way, or gaps appear around code blocks.
- **Icons:** `lib/icons.ts` holds the curated lucide icon map (keys are stored in `sets.icon`/`collections.icon`, so never rename one), the color map, and `suggestIcon(name)`. `ItemIcon` renders the tile; `IconPicker` is the picker sheet. A null icon/color falls back to the set or collection default.
- **Import/export:** `lib/cardFormat.ts` holds both `parseCards` (import page) and `exportCards` (Export button on the set page), so the tab format round-trips. `[type]` and `[match]` prefixes mark typed and matching cards; an answer of exactly True/False makes a true/false card.
- **Card types:** `components/CardForm.tsx` is the shared create/edit form. In study, `components/StudyInteractions.tsx` has the typed input, true/false buttons, and matching board. `lib/answerCheck.ts` grades typed answers (ignores markup, case, accents, spacing, a leading article, and small typos; numbers must match exactly). Auto-checks are only shown to the user, never stored: FSRS and accuracy come solely from the rating button tapped.
- **Card display:** `components/CardPreview.tsx` has `FlipCard` (tap to flip, optional swipe-to-dismiss), used by the Cards-tab preview modal and study View mode. Its `card-enter` animation must only play on mount; re-applying it after a flip causes a double rotation. While the back shows, `FlipCard` and the study card pin `minHeight` to the front's height, so a shorter back never shrinks the card (a longer one still grows it). Flipping back to the front clears it, so the front returns to its own size.
- **Sharing:** `ShareButton` (set and collection headers) makes a private item public after confirming, then opens the native share sheet or copies the link. `AuthGuard` stores the requested path in sessionStorage before redirecting to `/login`, and returns there after sign-in.
- **Organizing sets:** `components/SetOrganizer.tsx` (home and collection pages). Long-press or Select enters selection mode (bulk Move / Public-Private / Delete, Undo toast). Drag uses dnd-kit and only starts from the handle shown in selection mode (mouse and touch), so sets can't be moved by accident. Dropping on a collection card moves the set. Reordering writes `sets.position` via `reorder_sets`; `sortSets()` in `lib/sets.ts` mirrors the DB order.
- **Set page Cards tab:** search matches question/answer/options/pairs text, and `#12` (or a bare `12`) finds card number 12. Owners can drag cards to reorder (mouse: anywhere on the card; touch: the grip in selection mode; off while searching/filtering; saved via the `reorder_cards(card_ids, positions)` RPC). Owners can also long-press a card or tap Select to move cards to another set (progress comes along, `position` reset to null), reset their progress, or delete them. Import and Export share one dropdown.
- **Editor copy/paste:** highlighting a code card and copying gives the full fenced block (`CodeBlockCard` onCopy). Math nodes store `data-latex`/`data-display` so rich copies paste back exactly, and `MathInSelection` highlights equations inside a text selection. `RichTextBlock` handlePaste rebuilds plain-text markup: code fences re-split the block via `onPasteBlocks`, and other markup (`$…$`, bold, lists…) is inserted as parsed content. Clipboard data with HTML takes the default paste.
- **Editor selection and Tab:** each text block is its own contenteditable, and browsers won't drag a selection out of one. BlockEditor's cross-block selection turns every text block read-only (`setEditable(false, false)`) once a drag leaves its starting block, snaps code blocks in whole, and on copy/cut/Backspace/Delete serializes or removes the span as markup (`data-block-idx` marks each block). The next click or keypress makes the blocks editable again. Tab in a text block moves to the next field (`focusAdjacentField`; a whole BlockEditor, `[data-field-editor]`, counts as one field). In a code block, Tab indents and Shift+Tab un-indents (`indentCode`). The editable element fills the box's min height so a click anywhere in it starts typing.
- **Copying:** equations render with `data-latex` + `select-all`, and `components/CopyAsSource.tsx` (mounted in the root layout) rewrites a copied selection so equations become `$…$`. Editor math nodes copy as LaTeX via `renderText`. In the editor, only a code card's grip is draggable, so the code can be selected.
- **Installed-app gestures:** `components/StandaloneGestures.tsx` (root layout, home-screen app only) blocks the iOS edge-swipe back/forward by cancelling touches in the outer 16px, and adds pull-to-refresh at the top of the page (reloads). A pull won't start while a modal has locked body scroll, or on `.touch-none`, inputs, or `[data-no-pull]`. Keep tappable UI out of the 16px side gutters.
- **Quick actions:** on the set page, ` opens a numbered menu (`components/QuickActions.tsx`) and a number key runs that action: owners get 1 Add card, 2 Import, 3 Study, 4 View, 5 Export, 6 Select, 7 Settings. Keep the order fixed (unavailable actions are greyed out, not removed) so the shortcuts stay the same.
- **Desktop layout (lg, 1024px+):** `components/AppShell.tsx` (root layout) adds a fixed left sidebar: New set, My Sets / Discover / Friends, the user's collections (from the cache; `cacheCollections` fires `COLLECTIONS_EVENT` so it stays current), theme and sign out. Study pages and `/login` get no sidebar. Bars fixed to the bottom of the screen need the `fixed-bar` class so they start right of the sidebar. Home, collection and set pages widen to `lg:max-w-6xl` (sets and collections in a 2–3 column grid; SetOrganizer switches to `rectSortingStrategy` and free 2D drag via `useMediaQuery(DESKTOP_QUERY)`), the set page splits into a sticky left column (header, stats, Study) and the card list, forms widen to `lg:max-w-2xl`, and study to `lg:max-w-3xl`. Phones are unchanged. The home tab is in the URL (`/?tab=discover`) so the sidebar can link to it.
- **Study keyboard shortcuts:** Space/Enter shows the answer, and after that Space flips between the sides (ratings stay available on both). 1–4 rate, A–D (or 1–n) pick a multiple-choice option, T/F answer true/false, Z or ⌘Z/Ctrl+Z undoes, `-` buries, `@` suspends (Anki's keys), ←/→ in View mode. `FlipCard` (View mode, card preview) handles Space itself. Ignored while typing in an input. Key hints (`Kbd`) show on desktop only.
- **Undo, bury, suspend** (study header, `StudyAction` buttons, `UndoToast`):
  - Every rating, bury or suspend pushes an `UndoEntry` with the card's previous progress, the previous queue and the session stats. Undo restores them: `saveProgress`, or `resetProgress` if the card had none. It also deletes the review-log row and gives back the day's new-card count.
  - Bury sets `buried_until` to the next study day; suspend sets `suspended`. Both live on the progress row. `isAvailable` keeps such cards out of every queue (regular and custom study).
  - Suspended cards are unsuspended from the set page: Select, then Unsuspend (`store.setSuspended`). That page also has a Suspended filter chip and Suspended/Buried badges.
  - Study days start at 4 AM local (`lib/day.ts`), for burying, the daily new-card count and stats.
- **Review log and stats:**
  - Each rating writes a `ReviewLog` (`store.logReview`). It holds the state before the review, days since the last one and its interval, the new interval/stability/difficulty, and time on the card (capped at 5 minutes). Offline web ratings queue them (`queueReview`) next to the progress queue.
  - `/stats` (sidebar, phone home header, set page link, set quick action 8; `?set=` / `?collection=`) computes everything client-side in `lib/stats.ts`. Charts are hand-made in `components/stats/Charts.tsx`; no chart library.
  - Days before the log's first entry come from session totals (`store.getStudyHistory`: sessions plus rollups).
- **Reversed cards:**
  - `flashcards.reverse` (open-ended and typed only, `canReverse`) means the card is also studied back to front.
  - Each direction has its own progress, its `ord`: `card_progress.ord`, unique on (user_id, card_id, ord); on desktop, `progress.json` keys `"<id>"` and `"<id>:1"` (`progressKey`). `FlashcardWithProgress.progress` is ord 0 and `extraProgress[1]` is the reverse.
  - Study queues are of items (card plus ord: `studyItems` / `toItems`). `cardFace` swaps the faces for ord 1, and every progress, undo and review-log path carries the ord. Rating one direction buries the other until the next day (sibling burying), and undo restores it.
  - Stats, the due count and the optimizer count directions; the card list and the set size count cards.
  - Set up by the CardForm checkbox, or a `[reverse]` tag in the text format (export writes it).
  - Anki notes whose two templates mirror each other ("Basic (and reversed card)", `isMirrored`) import as one reversed card.
- **Study settings and FSRS optimization:**
  - `/settings` (sidebar; the Stats header on phones) holds the user's `StudySettings`: target retention, new-day hour, and FSRS parameters. They're stored with `store.get/saveSettings` (web: `user_settings` table; desktop: `library.json`), and `lib/studySettings.ts` caches them in localStorage (`fc_study_settings`, which `lib/day.ts` also reads for the hour).
  - A set's `desired_retention` overrides the target. The study page builds its scheduler with `scheduler(retentionFor(set, settings), settings)`, so always build schedulers that way, never with a bare `fsrs()`.
  - `/optimize` runs fsrs-rs (Anki's optimizer) compiled to wasm (`fsrs-browser`, via `lib/optimizer.ts`). It feeds it the review log as Anki revlog columns (`computeParametersAnki`), then `evaluate` replays the user's history and compares log loss for the current vs new parameters before they choose.
  - Both optimizers get the same input: `trainingItems` (Anki's revlog conversion, ported from fsrs-rs). The desktop app runs fsrs-rs natively first (`optimize_fsrs` in `src-tauri/src/lib.rs`, crate `fsrs` 6.6, the version inside fsrs-browser), because the Mac app's WebKit window ignores COOP/COEP. It falls back to the wasm when isolated.
  - The wasm trains on threads, which needs a **cross-origin isolated** page. On the web, only `/optimize` gets COOP/COEP (`next.config.ts` `headers()`): those headers block cross-origin images like Google avatars, so the page has no sidebar (`isBare`), and it must be reached with a full page load (plain `<a href={paths.optimize}>`, not `<Link>`). The desktop app sends the headers for every page (`tauri.conf.json` `app.security.headers`), so everything it loads must stay same-origin, or CORS/blob. `canOptimize()` checks for isolation and the page explains when it isn't available.
  - Stats shows an "Optimize" nudge once 400+ reviews have accumulated since `reviewsAtOptimize`.
- **Version history:** `/changelog` renders `CHANGELOG` from `lib/changelog.ts`. The sidebar shows "What's new · v…" and phones get a link at the bottom of home. The version is package.json's, passed in as `NEXT_PUBLIC_APP_VERSION` by `next.config.ts`. **Add an entry with every release**, written for users.
- **Home tabs:** My Sets (client-side search over cached sets plus an All / Collections / Sets filter; no tag chips, `#tag` in the search box matches tags by prefix, same in Discover), Discover (`components/DiscoverTab.tsx`, calls the `discover_sets` RPC), Friends.
- **Study controls:** Show Answer, the FSRS rating buttons, and View mode Back/Next live in `components/BottomBar.tsx` (fixed to the bottom of the screen). Pages using it end with `<BottomBarSpacer />`, which is always rendered so the layout doesn't shift.
- **View mode:** the set page's View button opens `/sets/[id]/study?mode=view`. It browses every card in set order. The progress bar is a draggable scrubber (`.scrubber` range input, styled in `globals.css`) for jumping to any card.

## Desktop app (Tauri)

One codebase, two builds, chosen by `NEXT_PUBLIC_TARGET` (`IS_DESKTOP` in `lib/platform.ts`, a build-time constant):
- **Store:** `lib/store/types.ts` defines `Store`, everything the app does with the user's own data. `supabaseStore` is the web version (the queries that used to live in pages). `localStore` is the desktop version over a library folder, through `Files` (`lib/store/files.ts`: `tauriFiles` for the real folder, `memoryFiles` for `dev:desktop` in a browser). `lib/store/desktop.ts` opens the remembered folder and forwards calls to it. New data features go through `Store`, implemented in both.
- **Library layout:** `library.json` (version, collections), and `sets/<id>/` holding `set.json`, `cards.json`, `progress.json` ({cardId: FSRS}), and `sessions.json`, plus `reviews/<YYYY-MM>.json` (the review log for all sets by month, read on demand, so moving a card never rewrites history; reviews map to a card's current set when read). The rest of the library is loaded into memory, and each change rewrites only the file it touched (temp file, then rename). Adding a column means updating `localStore` and `lib/libraryZip.ts` too.
- **No accounts on desktop:** `AuthGuard` shows `LibraryGate` (choose a folder on first launch) and provides a local user (`id: 'local'`, which is `user_id` on every local row). Friends, Discover, sharing, and the public/private toggles are hidden with `IS_DESKTOP`. Sets can hold up to 100,000 cards (`store.maxCardsPerSet`).
- **Routes:** the desktop build is a static export, which can't have a page per id. Its layouts (`desktop/overrides/app/**`) build each dynamic route once for the id `_`, and the real ids go in the query string. So **links to set and collection pages must use `paths` (`lib/paths.ts`), and pages read ids with `useRouteIds()`**, never template strings or `useParams`.
- **Desktop builds go through `scripts/desktop.mjs`** (`dev:desktop`, `build:desktop`, and Tauri's before-commands). While Next runs, it copies `desktop/overrides/**` over the matching `app/` files and sets the web-only routes (preview images, `/create`, `/study`) aside in `.desktop-swap/`, then restores them. If a run was killed, `node scripts/desktop.mjs restore` puts them back. Don't use `pageExtensions` (e.g. `*.web.tsx`) to split the builds: Next then skips `route_client-reference-manifest.js` for preview-image routes, and Vercel's deploy fails.
- **Images (desktop only):** `prepareImage` (`lib/images.ts`) scales pictures to 1600px max and re-encodes them as WebP (PNG in the Mac app, since Safari can't encode WebP; the extension follows what the encoder returned). `store.saveImage` writes them to the library's `images/` folder, named by content hash (so duplicates are stored once), and `store.imageUrl` reads them back as object URLs. Unused images are pruned when the library opens (`pruneImages`), never mid-session, because a card being edited may use an image it hasn't saved yet. `CardImage` renders them, or a placeholder on the web. The editor's `ImageBlock` node is in both builds, so an image line survives editing anywhere, but inserting (paste, drop, `/image`) is desktop-only.
- **Getting the app:** the web sidebar shows `DesktopAppPromo` on Windows and Mac (dismissible, remembered per platform). It links to the newest `-setup.exe` or `.dmg`, found through the GitHub releases API, falling back to the Releases page.
- **Transfer (library zip, every direction: web ⇄ desktop, Windows ⇄ Mac):**
  - A library zip has the desktop folder layout: sets, progress (both directions), sessions, `reviews/`, `library.json` with collections and settings, and images (from desktop only). `lib/libraryTransfer.ts` reads it, writes it, and delivers it (a save dialog in the app, `dialog:allow-save`; a download on the web).
  - Both sidebars have Export (↓, `/library/export`, all or chosen sets) and Import (`/library/import`). Each explains itself first.
  - Building and merging: desktop uses `exportBundle` / `importBundle` (`lib/store/desktop.ts`, on raw files, then reopens the store); web uses `exportWebBundle` / `importWebBundle` (`lib/webLibrary.ts`, Supabase directly).
  - Importing never deletes or overwrites. It adds missing collections, sets, cards (by id), reviews (by id) and images. For progress the newer `last_review` wins, and settings are taken only if there are none.
  - On the web, sets over 3,000 cards split into "(part N)" sets, and media stays behind as placeholders. Web exports carry session history as sessions (rollup days at noon), not `imported_stats`; older zips with `imported_stats` still work.
  - New set or card columns must be added to `importWebBundle`'s `cardRow` and its set insert.
- **Library folder:** the sidebar's folder name and folder button open `/library/folder`, which explains the library folder and switches to another.
- **Shell:** `src-tauri/` is only plugin registration (fs, persisted-scope, dialog, updater, process); permissions are in `capabilities/default.json`. File access is limited to the folder the user picked. The window sets `dragDropEnabled: false`, or Tauri swallows files dropped from outside (and all HTML5 drag-and-drop) before the page sees them. Use `confirmAction` / `notify` (`lib/dialogs.ts`) instead of `confirm()` / `alert()` in anything the desktop app shows: in the app they become native dialogs (`dialog:allow-message`), because the Mac window (WebKit) may not show the browser's own. Only web-only code (sharing, friends) calls them directly. The picker must pass `recursive: true`, or only the folder's top level is granted and writes under `sets/` fail.
- **Releases:** add the version's entry to `lib/changelog.ts`, then `npm version patch` and `git push --follow-tags`. The `v*` tag runs `.github/workflows/desktop-release.yml`, which builds the Windows installer and then (so the two never write `latest.json` at once) a universal Mac `.dmg`, signs the updates with the `TAURI_SIGNING_PRIVATE_KEY` secret (key file in `~/.tauri/flashcards.key` on the owner's PC; the public key is in `tauri.conf.json`), and publishes a GitHub Release with `latest.json`. Installed apps check it on launch, hourly, and when the window regains focus (at most every 10 minutes), and offer "Update to … and restart" in the sidebar. They never update without a click. Pushing other branches runs `desktop-build.yml`, a test build whose Windows installer and Mac `.dmg` are attached to the run.
- **Mac:** `src-tauri/tauri.macos.conf.json` (merged in automatically on macOS) sets the `app`/`dmg` targets and ad-hoc signing (`signingIdentity: "-"`). The app isn't notarized, so the first open needs System Settings → Privacy & Security → Open Anyway; updates install normally after that. Notarizing later means an Apple Developer account and adding its certificate secrets to the Mac job. The app window is WebKit (Safari's engine), not Chromium as on Windows.

## Anki import

`/import-anki` (home "+ New" menu, both builds) turns an Anki `.apkg` or text export into sets. Cards always start as new, and images come along on desktop only. `lib/anki/`:
- `apkg.ts` reads every package format: `collection.anki21b` (zstd, schema 18, protobuf configs via a tiny reader), then `anki21`, then `anki2`, newest first, because newer packages include a stub `anki2`. It also reads JSON or protobuf media maps. SQLite runs through sql.js, with `public/sql-wasm.wasm` served locally so it works offline.
- `convert.ts`:
  - Cloze note types read the cloze field directly instead of rendering templates, which depend on JavaScript. One cloze outside math becomes `fill_blank` (`___` plus the hint). Clozes inside math, or cards with several blanks, become `open_ended`, with `\boxed{?}` in math and the answer in blue.
  - The back template, rendered with the cloze and front left empty, supplies the extras shown under the answer.
  - `{{cN::ask-ans}}` / `ask-all` markers ("Cloze Overlapping" note types) are supported.
  - Other note types render their templates (`template.ts`), keeping what's below `<hr id=answer>`. `{{Tags}}` renders empty.
  - Deck paths become sets; the top deck becomes a collection (`groupDecks`).
- `template.ts`: the cloze parser tracks nesting and LaTeX braces, so `}}` inside `\frac{a}{b}}}` doesn't close a cloze early.
- `html.ts` converts HTML to markup through Tiptap JSON and `serializeMarkup`.
  - MathJax is pulled out of the raw HTML first, as `<anki-math>` placeholders, so equations that span tags stay whole.
  - Dropped: scripts, form controls, hidden elements (inline styles or the note type's CSS, `hiddenSelectors`), images inside outside links (badges and ads), and `<details>` with nothing but a label.
  - `tidyRuns` fixes overlapping bold/italic, which the markup can't nest.
  - Boxes of instructions for Anki itself (text naming AnkiDroid/AnkiMobile; innermost container only) are dropped.
- Backs built by a script (template = `{{FrontSide}}` + `<script>`, so empty without JavaScript) get the note's fields the front doesn't use instead, minus ID-like fields (`isIdField`). Front-only "info" notes are split into heading (or first field) and the rest (`splitInfoNote`).
- MathJax-only LaTeX is fixed when rendering, not when importing, so old cards benefit too. `normalizeLatex` (`lib/latex.ts`, called by `renderMath`) does all of these; add new cases there:
  - inline `align`/`gather` → `aligned`/`gathered`
  - `\unicode{…}` → `\oiint` or `\char`
  - adds braces to script arguments like `_\vec{a}`
  - drops empty `\textcolor{}`
  - escapes `_` inside `\text{}`
  - plain-TeX `\array{…}` → a matrix
- `txt.ts` handles Anki's text exports (`#separator`, `#deck column` headers, quoted fields).

## Data model (Supabase, `public` schema)

- `collections` — folders that group sets (`name`, `description`, `tags text[]`, `icon`, `color`, `is_public`, `user_id`). A public collection shows only its public sets to others. RLS returns other people's public collections too, so filter by `user_id` when listing your own.
- `sets` — `name`, `description`, `is_public`, `tags text[]`, `icon`, `color`, `position` (manual home-screen order; set in bulk by the `reorder_sets(ids)` RPC), `collection_id` (nullable, `on delete set null`), `desired_retention` (nullable; personal, so `fork_set` doesn't copy it)
- `user_settings` — one row per user (`settings jsonb`, a `StudySettings`); own row only
- `flashcards` — `set_id`, `question`, `answer`, `type` (`open_ended` | `multiple_choice` | `fill_blank` | `typed` | `true_false` | `matching`), `options text[]` (MC choices; extra accepted answers for `typed`), `pairs jsonb` (`[{left, right}]`, matching only), `position`. Type labels and badges live in `lib/cardTypes.ts`.
- `card_progress` — per-user FSRS state per card, plus `suspended` and `buried_until`
- `review_logs` — one row per rating (own rows only; cascades with the card). Never rolled up: stats and FSRS optimization need every review. `set_id` is where the card was then; `getReviews` joins `flashcards` so moved cards count for their current set.
- `study_sessions` — one row per completed/exited study session. A nightly pg_cron job (`rollup-old-study-sessions`, 03:17 UTC) runs `rollup_old_sessions()`, which moves sessions older than 90 days into `study_rollups` (one row per user, set and UTC day). Read totals from the `set_study_stats` view (security_invoker; sums both tables per user and set), never from `study_sessions` alone, or older history goes missing. The home cards, set page stats, and `get_friends_leaderboard()` all use it. There is no per-session History UI.
- `profiles`, `friend_requests` — social features; `get_friends_leaderboard()` and `fork_set()` RPCs. `fork_set` copies icon, color, tags, and `pairs`, so update it when adding set or card columns.
- `discover_sets(q, lim, off)` RPC — other users' public sets matching a name/description/tag search, with owner name and card count.

Schema changes go through Supabase migrations (the Supabase MCP server is configured in `.mcp.json`). Keep `lib/types.ts` in sync.

## Gotchas

- **PostgREST caps every response at 1000 rows.** Never `select` flashcards without paging. Use `fetchAllRows()` from `lib/fetchAll.ts`. For totals, use `count: 'exact', head: true` queries instead of downloading rows; `lib/sets.ts` does this for home-page stats.
- Sets are capped at `MAX_CARDS_PER_SET` (3000, in `lib/fetchAll.ts`). Enforce it anywhere cards are inserted.
- Card order is `position asc nulls last, created_at asc`. Newly created cards have `position = null`.
- "View" mode on the study page must never write `card_progress` or `study_sessions`.
- Unbreakable content widens the page on phones. Inline math is capped at `max-w-full` and scrolls inside the line; `body` has `overflow-wrap: break-word` for long words and `overflow-x-clip` as a last-resort guard (clip, not hidden, so `position: sticky` still works). Grid columns holding card content need `minmax(0,1fr)`, and flex items need `min-w-0`.
- Cards use CSS transform animations, which trap `position: fixed` descendants. Overlays opened from inside a card (code fullscreen, math popup) must `createPortal` to `document.body` and stop event propagation, because React events still bubble through portals to the card's flip handler.

## Conventions

- Set/collection names render through `noOrphan()` (`lib/text.ts`, glues the last words with non-breaking spaces so a wrapped name never ends in a tiny fragment) plus `text-pretty`. Don't use `text-balance` on titles: it wraps too early on phones.
- Tailwind only (its `content` includes `lib/` because `lib/icons.ts` defines color classes), with a `dark:` variant on every color. Palette: indigo primary, gray neutrals, rounded-xl/2xl cards.
- Layout is `max-w-lg mx-auto px-4 py-6` per page. Modals use a `fixed inset-0 bg-black/50` backdrop.
- Imports use the `@/` alias. Column-aligned `useState` declarations are the house style.
